# 3D scenes

This is 3D in a Mac app made natively. A 3D game is made web by default, on the Mac as elsewhere (the game and
3d-game skills); it's made here only when the person asked for a native game, or it's a Mac app already made in Swift.

3D scenes (a world to move through, a room, a thing to turn over and handle): RealityKit through LampSceneView, from Sources/LampScene.swift, which Lamp adds to an app whose code imports RealityKit (the app then needs macOS 15). `LampSceneView(sky:camera:props:build:update:)`: sky `.day`, `.sunset`, `.overcast`, `.night`, `.studio`; camera `.orbit(target:distance:)`, `.chase("entity name")`, `.firstPerson()`, `.fixed(position:lookAt:)` or `.manual`; `build` adds entities to `scene.root`; `update(scene, dt)` runs every frame, with `scene.isDown(.w)` for keys. In a file that imports RealityKit, SwiftUI's `Scene` must be written `SwiftUI.Scene`.

Things are made in code, in meters, from LampMesh (`box(size, corner:)`, `sphere`, `cylinder`, `cone`, `lathe([[radius, height], …])` for anything round, `extrude(path, depth:, chamfer:)`, `sweep(path, along:)`, `tube(along:radius:)`, `plane(width:depth:tile:)`, `text`) and LampMaterial (`metal`, `chrome`, `brushed`, `plastic`, `rubber`, `glass`, `paint`, `wood`, `fabric`, `ceramic`, `concrete`, `asphalt`, `brick`, `tiles`, `grass`, `glow`). A prop is a function returning one Entity of named parts at real size; the parts that move are `lampPress { }`, `lampTurn(axis:range:)`, `lampSlide(axis:range:)` and `lampGrab()`; `lampPhysics(.dynamic)` or `.static` for falling and knocking; `lampShadow()` under anything standing on the ground. Many copies of one thing go in one `LampScene.copies(of:at:)`. A world bigger than a few hundred meters (a town, a map, a landscape) is streamed, never built whole at launch: `scene.stream(tile: 100, radius: 400, around: { car.position }) { tile in … }` returns what's drawn on one tile (share things out with `tile.contains`), made as it comes into reach, by a named function (`{ tile in World.tile(tile) }`) so a change to it shows in the open app (anything else the app draws itself and should redraw after a change goes in LampSceneView's `onLiveChange`). A change that reshapes the view holding the LampSceneView gives it a fresh scene while the app's own objects carry on, so its `build` runs again on the same game: make `build` start clean (empty the lists, physics bodies and handles it fills, or make them anew) rather than add to what the last build left; what the game needs everywhere (collisions, routes, the map's data) is made once, outside it.

Keep it smooth: a frame has about 16 ms, and anything the app does while it's open (a frame's update, a tile, a prop that appears in play, a level loading) takes from it, so a slow piece is a stutter. Make each mesh, material, texture and piece of text once and reuse it (`copies` for many of one thing, one text mesh per distinct word), never the same thing again per place; turn heavy data (a map, a level) into a compact file in Assets/ while building, not at launch; keep per-frame work to what moves. A streamed tile should take a few milliseconds: the log names slower ones. When a tile has much to work out (a town's buildings and roads from map data), split it so that work leaves the main thread: `scene.stream(tile:radius:around:, prepare: { World.plan($0) }, make: { World.tile($0, $1) })`, where `plan` returns a `Sendable` struct of what's on the tile (its shapes as filled `LampMeshBuilder`s, positions, colors) and runs on other cores, several tiles at once, touching no entity, material or state the app changes, and `make` turns it into entities on the main thread with `LampMesh.make(builders)` and shared materials, in a millisecond or two.

Physics is RealityKit's own; nothing else is added for it. Most scenes need none: a thing moved by the app's own rules (a car along a road, a door that swings when clicked) is moved in `update`, and what it touches is tested there (distances, bounds). Use physics when things should behave like things: a stack that topples, balls that roll and knock into each other, something dropped, thrown or knocked over. `lampPhysics(.dynamic, mass:bounce:friction:)` makes a prop fall and be knocked about and `.static` what it lands on, from a `PhysicsBodyComponent` and a `CollisionComponent`. Its collision shape comes from its meshes unless the entity already has one, and for anything that moves it should: set `CollisionComponent(shapes: [.generateBox(size:)])` (or `.generateSphere(radius:)`, `.generateCapsule(height:radius:)`, several for a shape made of parts, `ShapeResource.generateConvex(from:)` for an odd one) before `lampPhysics`, never a detailed mesh. A body is `.dynamic` (moved only by physics: push it with `applyLinearImpulse(_:relativeTo:)` or `addForce(_:relativeTo:)`, never by setting its position each frame), `.static`, or `.kinematic` (moved by the app, pushing dynamic bodies without being pushed: a tilting board, a moving platform; give it a `PhysicsMotionComponent` velocity or move it in `update`). A fast small thing gets `isContinuousCollisionDetectionEnabled` on its body so it doesn't pass through thin walls. A player who walks, climbs steps and stands on slopes is a `CharacterControllerComponent(radius:height:skinWidth:slopeLimit:stepLimit:)` moved each frame with `moveCharacter(by:deltaTime:relativeTo:)`, gravity added by the app, `CharacterControllerStateComponent`'s `isOnGround` before a jump. Hinges, sliders, ball joints and welds are `PhysicsRevoluteJoint`, `PhysicsPrismaticJoint`, `PhysicsSphericalJoint` and `PhysicsFixedJoint` between two entities' pins (`entity.pins.set(named:position:orientation:)`), each `try joint.addToSimulation()`. RealityKit has no vehicle: a car the person drives is moved by the app, as most are. Collisions arrive as `CollisionEvents.Began` from the scene the world is in, which can change when the view is made again: in `update`, subscribe when `scene.root.scene` isn't the one subscribed to, keep the `EventSubscription`, and use the event for sounds and scores; a `CollisionComponent` with `mode: .trigger` is a zone felt but not hit (a goal, a pickup). Physics costs a frame's time too: resting bodies sleep by themselves, so leave them be; keep to a few hundred dynamic bodies, the simplest shapes that do, and no body made per frame.

Model a real thing from a picture of it, never from memory alone. Before writing a main prop that is a real object (a car model, a building, a piece of furniture, an animal), get a reference: the person's photo from the chat, else one `make_art` of the object alone on a plain background, seen straight from the side (or the front, for something whose face matters), whole and uncropped. Read off it what code needs: its outline, proportions (length to height, where the parts begin and end), colors and the parts that make it recognizable. Small or generic props (a box, a pole, a cup) need none.

Each prop that matters goes in `props` by name, and look_at_app with `prop` shows it on its own from four sides. Every distinct object made by its own function (a vehicle, a character, furniture, a machine) is a prop, the player's or main object first, and goes into the scene with `scene.place("car", at:heading:)`, which returns the entity to keep and move: so placed, a change to its code shows in the open app; other changes to the scene show when it reopens. Compare that with the reference: shape, proportions, colors, parts. Fix and look again, up to three rounds for the main props; background things get one look.

LampSceneView already avoids RealityKit's flicker; keep it that way: no sun shadows (they make the whole picture flicker; `lampShadow` instead), and flat things laid on others (roads, markings, decals, a sign's writing) a few centimeters above them, never at the same height. After big changes, look_at_app with `motion`.

A model code can't reasonably make can come from a free CC0 library (Kenney, Poly Haven) as .glb: download it into Assets/, turn it into USD with `usdextract -o Assets/Name file.glb` (part of macOS), and load it with `try await Entity(contentsOf: LampAssets.url("Name/name.usdc")!)`.

A real place (a town to drive, a campus, a neighborhood) is built from map data: open the maps skill too.
